## Scope and evidence rules

Audit only: production operations, the complete public and local demo-account journey, shipped feature readiness and existing roadmap, performance, and guidance eligible through 2026-09-30. Application code, deployment controls, secrets, security policy, test thresholds, dependency versions, and remote data remain unchanged. Root preview resources are treated as production unless isolation is independently proven. Only ordinary public read-only requests and public demo-login session issuance are permitted remotely; every other mutation belongs in a fresh disposable local environment.

Evidence classes: `source-only` (checkout source/config); `local-runtime` (isolated local execution); `deployed-runtime` (observed target behavior/config); `historical` (dated prior record); `unverified` (not observed or prerequisite unavailable). Mocked tests and source inspections never establish deployed behavior. Prior closure notes remain historical and are not rewritten. Priorities are scheduling order, not vulnerability severity. No certification is claimed.

Each ledger row must include the requirement, source anchor, evidence class, exact command/action, expected and observed result, UTC execution time, evidence artifact, priority, responsible role, existing owner plan, and executable acceptance contract. A skipped check must name its blocker and required role.
