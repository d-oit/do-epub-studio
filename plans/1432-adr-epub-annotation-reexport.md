# ADR-1432 — Additive, bounded EPUB annotation export

**Status:** Accepted

## Context

The existing export route returns Markdown/HTML, while annotation interchange is JSON. EPUB export must copy the authorized original revision, retain existing resources/metadata, safely represent all user annotations, and validate the exact downloadable bytes. Worker memory is bounded; stored locators and text are untrusted.

## Decision

1. Keep the source publication resources and metadata values unchanged. Add one XHTML annotation appendix and only the required OPF manifest/spine/navigation entries. The appendix uses standard XHTML/EPUB structural semantics and relative links to known package resources.
2. Resolve locators only against exact normalized OPF manifest/spine paths. Validate CFI syntax and confirm its spine target before using a CFI link. Do not use a locator as a filesystem/archive path or network target. Escape all user text; unresolved/stale records remain marked with available original/current chapter and text context.
3. Enforce source compressed bytes ≤8 MiB, source expanded bytes ≤16 MiB, generated compressed bytes ≤10 MiB, generated expanded bytes ≤24 MiB, ≤2,000 archive entries, ≤500 annotations, and ≤1 MiB aggregate annotation text. Reject limits rather than truncate or omit data. Enforce generated ZIP output size incrementally.
4. Reuse the existing fixed-path bearer-authenticated EPUBCheck runner synchronously. A successful response requires accepted archive safety, a valid runner result whose SHA-256 matches the generated bytes, and no EPUBCheck error findings. Runner absence/failure is fail-closed.
5. Preserve the existing Markdown implementation as a local/offline path. HTML remains the existing JSON export. EPUB uses an authenticated binary response and the format selector. The JSON interchange route remains independent.

## Consequences

- Large books/annotation collections receive explicit 413 errors; they cannot consume unbounded Worker memory.
- EPUB export depends on the configured validator and can take up to the runner's bounded runtime. No result is reported successful while validation is unavailable.
- Source links are emitted only when the target is proven; incomplete/stale data stays available in the appendix without a guessed destination.
- Original content text/resources and metadata are not re-authored; only package/navigation references and the new appendix are added.
- Existing upload validation, storage schema, and Markdown/HTML response contracts do not change.

## Alternatives rejected

- Rebuild the publication with the authoring packager: loses arbitrary source metadata/resources.
- Return unvalidated output when EPUBCheck is unavailable: violates correctness and creates false success.
- Embed unescaped annotation HTML or fetch annotation URIs: executable markup/SSRF risk.
- Truncate annotations or fall back to Markdown: silently loses requested content and misrepresents the selected format.
- Encode EPUB bytes as JSON/base64: adds copies and unnecessary memory while obscuring the binary contract.
