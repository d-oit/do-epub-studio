# EPUB Capability Matrix

This is an evidence-bounded reader capability inventory, not a claim that a file is conformant or accessible. **EPUB 3.3** and **EPUB Accessibility 1.1** are the normative W3C Recommendation baselines. **EPUB 3.4** (Candidate Recommendation Draft, 2 November 2026) and **EPUB Accessibility 1.2** (Candidate Recommendation Draft, 12 September 2026) are forward-looking specifications and are **not** normative replacements; this matrix makes no EPUB 3.4 or EPUB Accessibility 1.2 support claim. EPUB package documents produced by this corpus use version `3.0` for EPUB 3 publications (the package version does not encode the later 3.1/3.2/3.3 specification edition).

Unless a row says otherwise, its engine baseline is reader-core's locked `@intity/epub-js` 0.3.96; the browser observations refer to Playwright-managed Chromium/WebKit engines (`1.65.0`). The fixture assertions are the evidence for each row, and reader-engine behavior not exercised by those assertions remains partial or manual review rather than inferred from parser acceptance.

## Evidence and classification

- **Conformance**: synthetic package structure has an explicit fixture assertion; this is not a substitute for EPUBCheck. No conformance certification is claimed.
- **Advisory**: the reader preserves/displays or exposes a feature on a best-effort basis; semantic correctness and assistive-technology experience require review.
- **Manual review**: no automated support claim; validate with actual reading systems and assistive technology before relying on it.
- `packages/reader-core` generates the corpus via `pnpm --filter @do-epub-studio/reader-core fixtures:capabilities`. Vitest checks the identifying package/content behavior and runs the two generated security examples through the EPUB sanitizer. Generated `.epub` binaries are ignored and must not be committed.
- Browser capability tests exercise both native browser baseline rendering and the production reader engine loading synthetic EPUB packages through the app's signed-file reader stack (`@intity/epub-js` 0.3.96). Execute with `PLAYWRIGHT_INCLUDE_WEBKIT=1 pnpm exec playwright test apps/tests/epub-capability-smoke.spec.ts --project=chromium --project=webkit`. Playwright is pinned by `package.json` / `pnpm-lock.yaml`; the browser binaries are the Playwright-managed Chromium/WebKit builds installed in the runner.
- Fixture provenance: all passages, labels, examples, SVG, table and metadata are newly written, short synthetic content. The remote-resource sample contains only a reserved `.example` URL and is never fetched. The media-overlay sample contains synthetic local MP3 audio and SMIL timing data mapping synchronized phrase boundaries in the reader engine.

## Validator scope vs. reader compatibility

Validator coverage, reader-engine rendering, and accessibility assessment are three distinct evidence categories and must not be conflated:

- **Validator coverage (`EPUBCheck 5.4.0`)**: Both `apps/epubcheck-runner` and CI fixture validation (`scripts/check-epub-fixtures.mjs`) are pinned to [EPUBCheck 5.4.0](https://github.com/w3c/epubcheck/releases/tag/v5.4.0). Any EPUB 3.4-era structural or schema checks executed by EPUBCheck 5.4.0 measure package conformance against validator rules only. A clean EPUBCheck pass **does not** establish that `@intity/epub-js` 0.3.96 or this reader UI renders or supports a feature.
- **Reader-engine compatibility**: Determined solely by observed rendering and behavioral tests in the sandboxed reader (`@intity/epub-js` 0.3.96 + DOMPurify sanitizer in `apps/tests/epub-capability-smoke.spec.ts` and `packages/reader-core` unit tests).
- **Accessibility assessment**: App-owned UI scans (axe-core / WCAG 2.2 AA target) and manual keyboard/assistive-technology records (`docs/accessibility.md`, `docs/accessibility-manual-test-record.md`) are distinct from EPUBCheck checks and OPF `schema:accessibility*` metadata.

## Reproducibility

Fixture generation is deterministic and uses only Node built-ins. Run the reader-core tests to generate the ordinary corpus and capability corpus before Vitest; `pnpm --filter @do-epub-studio/reader-core fixtures:capabilities` generates only the capability corpus. Run `pnpm check:epub-fixtures` (with Java available) to invoke pinned EPUBCheck `5.4.0` against the generated capability corpus and emit `epubcheck-report.json`.

## Review cadence

- **Standards status revisit triggers**: Review and refresh this matrix, `plans/1017-adr-epub-conformance-and-evidence.md`, and linked standards references at least quarterly, and immediately whenever:
  1. W3C advances **EPUB 3.4**, **EPUB Accessibility 1.2**, or **EPUB Annotations 1.0** to a new maturity level (e.g., Candidate Recommendation Snapshot, Proposed Recommendation, or Recommendation).
  2. The pinned validator (`apps/epubcheck-runner` / `scripts/check-epub-fixtures.mjs` EPUBCheck `5.4.0`) or reading engine (`@intity/epub-js` `0.3.96`) is upgraded.
- **Automated consistency check**: Run `node scripts/check-standards-status.mjs` to verify that standards-status statements, W3C status dates, pinned EPUBCheck version, and links remain consistent across the capability matrix and ADR-1017.
