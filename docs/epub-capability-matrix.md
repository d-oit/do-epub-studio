# EPUB Capability Matrix

This is an evidence-bounded reader capability inventory, not a claim that a file is conformant or accessible. EPUB 3.3 is the W3C Recommendation baseline. EPUB 3.4 is a draft / forward-looking work item; this matrix makes no EPUB 3.4 support claim. EPUB package documents produced by this corpus use version `3.0` for EPUB 3 publications (the package version does not encode the later 3.1/3.2/3.3 specification edition).

Unless a row says otherwise, its engine baseline is reader-core's locked `@intity/epub-js` 0.3.96; the browser observations refer to Playwright 1.64.1's managed Chromium/WebKit engines. The fixture assertions are the evidence for each row, and reader-engine behavior not exercised by those assertions remains partial or manual review rather than inferred from parser acceptance.

## Evidence and classification

- **Conformance**: synthetic package structure has an explicit fixture assertion; this is not a substitute for EPUBCheck. No conformance certification is claimed.
- **Advisory**: the reader preserves/displays or exposes a feature on a best-effort basis; semantic correctness and assistive-technology experience require review.
- **Manual review**: no automated support claim; validate with actual reading systems and assistive technology before relying on it.
- `packages/reader-core` generates the corpus via `pnpm --filter @do-epub-studio/reader-core fixtures:capabilities`. Vitest checks the identifying package/content behavior and runs the two generated security examples through the EPUB sanitizer. Generated `.epub` binaries are ignored and must not be committed.
- Browser capability tests exercise both native browser baseline rendering and the production reader engine loading synthetic EPUB packages through the app's signed-file reader stack (`@intity/epub-js` 0.3.96). Execute with `PLAYWRIGHT_INCLUDE_WEBKIT=1 pnpm exec playwright test apps/tests/epub-capability-smoke.spec.ts --project=chromium --project=webkit`. Playwright is pinned by the lockfile to 1.64.1; the browser binaries are the Playwright-managed Chromium/WebKit builds installed in the runner.
- Fixture provenance: all passages, labels, examples, SVG, table and metadata are newly written, short synthetic content. The remote-resource sample contains only a reserved `.example` URL and is never fetched. The media-overlay sample refers to a nonexistent audio asset and tests package structure only; no audio playback claim is made.

## Reproducibility

Fixture generation is deterministic and uses only Node built-ins. Run the reader-core tests to generate the ordinary corpus and capability corpus before Vitest; `pnpm --filter @do-epub-studio/reader-core fixtures:capabilities` generates only the capability corpus. This work adds no EPUBCheck CLI invocation: no official pinned CLI artifact/checksum was verified here, so the matrix must not be treated as validator output.
