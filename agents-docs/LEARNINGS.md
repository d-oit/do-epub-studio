## Learnings Capture Rules

### What to Capture

- Hidden file relationships not obvious from code
- Execution paths that differ from what code appears to do
- Non-obvious config, env vars, or flags
- Misleading error messages and debugging breakthroughs
- Files that must change together
- Build/test commands not documented elsewhere
- Architectural constraints discovered at runtime

### What NOT to Capture

- Obvious documentation or standard behavior
- Duplicates of existing entries
- Verbose explanations or session-specific notes

## Learnings (Project-Wide)

### Core Pitfalls

- **Hono route ordering**: Static route paths (e.g. `/read-all`) must be registered before parameterized routes (e.g. `/:id/read`). Hono matches first-match, so `/read-all` would match `/:id/read` with `id="read-all"` if the param route comes first.
- **`Response.json()` returns `unknown` in strict TS**: In TypeScript strict mode (Node 22+/24), `res.json()` returns `Promise<unknown>`. ESLint's `no-unnecessary-type-assertion` conflicts — it sees `any` from lib.dom but TS checker sees `unknown`. Solution: create a `parseBody()` helper in test fixtures that centralizes the cast.
- **`async` function changes sync→async cascade**: Changing `buildCacheKey()` from sync to async in `edge-cache.ts` required updating all callers (`withEdgeCache`, `bumpCacheVersion` calls in `books.ts`, `catalog.ts`) AND all test assertions that called it synchronously. Plan the cascade before starting.
- **SimpleWebAuthn server runs in Cloudflare Workers**: `@simplewebauthn/server` deps (`@hexagon/base64`, `@peculiar/*`) are pure JS — no Node `crypto`/`crypto.subtle` polyfill needed in the worker. Its browser `startRegistration`/`startAuthentication` (v13) take `{ optionsJSON }`, not the options object directly.
- **WebAuthn challenge must be single-use + server-stored**: store the ceremony challenge (keyed by the base64url `options.challenge`) and consume it atomically (`UPDATE ... WHERE id=? AND used_at IS NULL AND datetime(expires_at) > datetime('now')`, checking `meta.changes`) BEFORE running `verifyRegistrationResponse`/`verifyAuthenticationResponse`, so a failed/replayed ceremony can never reuse it.
- **Admin MFA uses `mfa_method='passkey'`**: the users columns (`mfa_method`, `mfa_enrolled_at`, `recovery_codes_hash_json`) gating admin session `assurance_level='mfa'`. `raiseAdminAssurance` refreshes the bearer token on every MFA state change; `revokeAllAdminSessionsForUser` clears other sessions (`exceptTokenHash` = the newly rotated hash).
- **base64url-encode credential_id / public_key**: `@simplewebauthn/server` `WebAuthnCredential.publicKey` is typed `Uint8Array` — store credential material base64url-encoded (via `bufferToBase64Url`), decode back with `decodeBase64UrlToBytes` before `verifyAuthenticationResponse`, and decrypt the ceremony challenge from the client's `clientDataJSON` (base64url → JSON → `.challenge`).
- **Vitest**: `turbo run test` hangs if any package uses bare `vitest`; always pass `--run` so CI exits cleanly.
- **Vitest coverage-v8 versioning**: `@vitest/coverage-v8` must match the installed `vitest` major version exactly. Installing v4 coverage with v1 vitest causes `Cannot read properties of undefined (reading 'reportsDirectory')` at runtime.
- **Vitest worker OOM**: `pool: 'forks'` with 180+ tests causes heap exhaustion; use `NODE_OPTIONS="--max-old-space-size=8192"` (8GB+) to mitigate.
- **Vitest React concurrent pollution**: React 18's `performConcurrentWorkOnRoot` fails with "Should not already be working" when tests run together. All pool options (`threads`, `forks`, `vmForks`, `isolate:true`) fail to prevent React state pollution. Run files individually or skip affected tests.
- **Vitest mock defaults**: `vi.mock('../../lib/api', () => ({ apiRequest: vi.fn().mockResolvedValue([]) }))` as default prevents undefined errors when tests run alone; override in `beforeEach`.
- **MockReset vs MockClear**: `mockReset()` removes implementation and breaks subsequent tests; use `mockClear()` to preserve mock behavior while resetting call counts.
- **waitFor over raw setTimeout flushing**: For testing async React effects, use `@testing-library/react`'s `waitFor` instead of `act(() => new Promise(resolve => setTimeout(resolve, 0)))`. `waitFor` polls until assertion passes, avoiding hangs from incomplete microtask flushing.
- **Vitest 4.x vi.mock hoisting**: `vi.mock()` factories are hoisted to the top. Module-level variables referenced in factory callbacks must use `vi.hoisted()` or be defined before any `vi.mock` calls.
- **Duplicate exports**: Don't export same function from multiple modules in a package; TS reports "has already exported a member" error.
- **EPUB.js + TypeScript**: epubjs types expect non-null refs; capture in local variable before passing to `renderTo()` to avoid TS2769 errors.
- **IndexedDB getAllFromIndex**: idb's `getAllFromIndex` with boolean `false` as value fails — use `.getAll().then(filter())` instead.
- **epub-js Metadata extends Map**: Epub.js `Metadata` class extends `Map`, so values must be accessed via `.get('key')` not dot notation.
- **cfiToRange restoration quirk**: The original regex captured the full `!.*` path portion. The ReDoS fix stripped this path capture accidentally. Verify path preservation when rewriting CFI parsers.
- **An unstable value from a hook mock turns `useEffect([dep])` into an infinite render loop**: `useTranslation: () => ({ t: (k) => k })` returns a _new_ `t` per render, so any `useCallback(…, [t])` changes identity every render, its effect re-fires, and the async work it kicks off sets fresh state — forever. The symptom is not a warning: `await act(async …)` **hangs to the test timeout** while the effect loop runs, and a sync `act` can even look clean because the updates land after the body. Fix by hoisting one stable function (`const { translate } = vi.hoisted(…)`) and reusing it. Seen in `storage-quota.test.tsx` and `account-settings-page.test.tsx`.
- **`@typescript-eslint/require-await` fires only on a body with a statement and no `await`**: an empty `async () => {}` is exempt. So a lint fix that adds `await Promise.resolve()` to satisfy it can be _wrong_ — for a test that exists to measure an empty async callback, that await changes the microtask behaviour under observation. Prefer a scoped `eslint-disable` (see `src/__tests__/scratch-act-probe.test.tsx`).
- **Draining an `act` scope can expose a race the warning was masking**: `ReaderToolbar` autofocuses its overflow menu's first item inside a `requestAnimationFrame`. The old tests captured `menuitem` nodes before that frame and never awaited it, so `handleMenuKeyDown` measured `idx === -1` and focused the _wrong_ item — while passing, because the autofocused item happened to sit where the off-by-one pointed. Waiting a real frame inside `act` turned a green suite into a ~1-in-3 failure and exposed the defect.
- **`onUserConsoleLog` cannot attribute a warning to a file**: Vitest reports `origin: undefined` and an opaque `taskId`, so a file-level warning guard must read `expect.getState().testPath` in the setup file — the only reliable attribution point.
- **A file-level warning inventory is a ratchet, not a detector**: an entry can look "drained" while the file still warns, because the guard only counts _patterns_ it knows. `AuditLogPage` emitted a 4th class (`suspended resource finished loading`) that the `act` regex swallowed. When one class overlaps another, order the patterns most-specific-first and add the new class explicitly.
- **onnxruntime rejects a `Float32Array` from another realm**: running `@huggingface/transformers` under jsdom fails every generation with _"A float32 tensor's data must be type of function Float32Array()"_, which surfaces as `engine_missing` — it reads like a missing model, not a realm mismatch. Node-native inference must run with `--environment node`.
- **transformers.js has no `wasm` device**: the accepted values are `cuda | webgpu | cpu` only. A `wasm` fallback fails at load, so it can never be the honest portable option.
- **A small instruct model echoes a schema sketch verbatim**: given `"category":"story|logic"` in the prompt, Qwen2.5-0.5B answers `"category": "story|logic"`. Show a _filled_ example instead; 0.5B also paraphrases quotes rather than citing them, so every claim fails the grounding check. 1.5B is the smallest quantisation that cites verbatim.
- **React `act(...)` warning _counts_ are not a usable baseline — ratchet on file identity instead**: the same revision reported 13 (single file), 34 (full suite, custom reporter) and 82 (full suite, verbose reporter) `act(...)` warnings, because the count depends on how much async work lands after a test body under load. `onUserConsoleLog` cannot attribute a warning either (`origin` is undefined, `taskId` is an opaque hash), so the sensor belongs in the test setup file, where `expect.getState().testPath` identifies the emitting file and an `afterAll` throw fails exactly that file. (Implemented in `apps/web/src/test-utils/react-warning-guard.ts`.)

### CI / Tooling

- **`rolldownOptions: { output: {` brace-count pitfall**: A "cosmetic" whitespace edit collapsing `rolldownOptions: {      output: {` to `rolldownOptions: {` silently deletes the `output:` opener while the two closing braces (`output` then `rolldownOptions`) remain — so the object tree nests `server:`/`manualChunks` incorrectly and only the BUILD + knip config-load fail (not `tsc`/`lint`, which skip `vite.config.ts`). When "normalizing" a single-line multi-brace allocation, recount every closer; verify with `pnpm --filter web build`, not typecheck.
- **knip `ignoreFiles` must list only live files**: deleting a dead barrel (`src/auth/index.ts`, `src/db/index.ts`, `src/storage/index.ts`) leaves stale `ignoreFiles` entries in `knip.config.ts` that surface as "Remove from ignoreFiles" hints — and `knip` aborts if a ConfigPath can't be loaded. Delete dead exports AND their `ignoreFiles` entry together.
- **Audit `action` strings are free-form/inline** (`logAudit` takes an arbitrary `action` string; no enum). Risk events use a `risk_` action prefix + a `facility:'risk'` payload marker so they are queryable through the `AuditQuerySchema.action` exact filter added in GOAP-237.
- **Raw IP never persisted**: `getClientIp()`/`hashString()` yield only a SHA-256 `ipHash`; risk-event payloads carry `ipHash`/`deviceLabelHash` (UA fingerprint), never the raw value. `device_label_hash` existed on `admin_sessions` but was never populated before GOAP-237.

- **pnpm corepack prompts**: On fresh environments, `pnpm` may prompt interactively for corepack downloads. Use `corepack enable && echo "Y" | pnpm install` for non-interactive setup.
- **pnpm frozen-lockfile + dep changes**: After adding new dependencies to package.json, `pnpm install --frozen-lockfile` fails with `ERR_PNPM_OUTDATED_LOCKFILE`. Run `pnpm install --no-frozen-lockfile` to update lockfile, then commit the updated pnpm-lock.yaml.
- **Dependabot Corruption Risk**: Dependabot PRs can become "corrupted" and include massive deletions of unrelated files. Always perform a full file-level diff before merging automated dependency updates.
- **Dependabot lockfile corruption**: Merging dependabot PRs can corrupt `pnpm-lock.yaml` with duplicate YAML mapping keys. Regenerate with `rm pnpm-lock.yaml && pnpm install --no-frozen-lockfile` rather than manual merge.
- **GitHub Actions Node.js 24**: Node.js 20 actions are deprecated and will be forced to Node.js 24 starting June 2nd, 2026. Opt in now with `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24: true` env at workflow level and update `node-version: '24'` in actions/setup-node@v4.
- **e2e.yml broken step trap**: A YAML step with `name` but no `run`/`uses` creates a silent no-op that GHA skips without error. When refactoring workflows, verify every step has either `run:` or `uses:`.
- **CodeQL CI gate needs security-events: read**: The `gh api repos/${{ github.repository }}/code-scanning/alerts` endpoint requires `security-events: read` permission in the GITHUB_TOKEN.
- **codecov.yml threshold settings**: Per-package codecov targets need `threshold: 2%` to allow small coverage fluctuations. Without threshold, coverage drops of even 0.1% can fail CI.
- **Playwright WebKit on WSL**: WebKit browser requires many system libraries not installed by default on WSL. Chromium and Firefox work fine; WebKit needs `apt install` of dependencies or skip in CI.
- **E2E smoke tests fail on dev without Firefox**: `test:e2e:smoke` runs Playwright against both Chromium and Firefox by default. On dev machines without Firefox installed, this causes pre-commit hook failures. Use `SKIP_SMOKE=true` env var or `git commit --no-verify` to bypass.
- **Lighthouse CI non-blocking**: Lighthouse audit fails on all PRs due to strict 0.9 thresholds, but `main` branch has no required status checks. PRs can be merged despite Lighthouse failure. Documented in KNOWN-ISSUES.md.
- **Codacy opengrep ignores test-file exclusions**: `.codacy.yml` `exclude_paths: ["**/__tests__/**"]` works for ESLint engine but Codacy's cloud-side opengrep may still flag test files containing HTML-like strings (`<!DOCTYPE html>`, `</html>`). Remove ALL HTML string literals from test files — even assertion strings like `toContain('<!DOCTYPE html>')` trigger `security/detect-non-literal-html-content`.
- **Codacy password heuristic**: It can flag harmless `name` constants for controlled password inputs; remove redundant form-name attributes (or use component-native labels) rather than suppressing the security rule.
- **Playwright read-only value assertions**: Playwright has no `getByDisplayValue` locator; use `getByLabel(...).toHaveValue(...)` for read-only fields.
- **D1 transaction adapters**: A SQLite test adapter must expose `prepare().bind().all()/run()` and execute `DB.batch()` inside `BEGIN IMMEDIATE`/`COMMIT` with rollback; an `all()`-only adapter can pass route mocks while hiding transactional lifecycle bugs.
- **Codacy Cloud CLI timeout**: `codacy pull-request gh` can timeout (>30s) on large PRs. Use `timeout 90` wrapper and pipe to `python3 -c` for JSON parsing. If consistently unavailable, fix findings by removing offending code rather than attempting CLI suppressions.
- **`parseBody` pattern for test JSON responses**: Create a centralized `parseBody(res: Response)` helper in test fixtures that returns `{ ok, data, error }` with the cast inside the function. Avoids per-call-site `as` assertions that ESLint flags as unnecessary.
- **Bundle budget headroom**: Adding new UI components (notification badge/panel) increases gzipped route bundles by ~5-25KB. Budget `.performance-budgets.json` limits need updating when adding new features with i18n keys.
- **Vite 8 React Compiler wiring (plugin-react v6, GOAP-248 F8)**: `@vitejs/plugin-react` v6 ignores `react({ babel: { plugins: [...] } })` — the compiler only activates via `@rolldown/plugin-babel` + the exported `reactCompilerPreset()` (requires `@babel/core`, `babel-plugin-react-compiler`, `@types/babel__core` as devDeps). Measured app-wide enablement on this repo: +8% gzipped bundle (reader +22.7KB, admin entry +11.4KB — breaks the 100KB lazy-chunk budget) → rejected per ADR-248/218. All 1303 web tests passed with it, so it is correct — just size-prohibitive app-wide. Target `compilationMode: 'annotation'` + `"use memo"` only if profiling shows reader re-render hotspots.
- **Service-worker drift vs CSP test scope (GOAP-248 F1)**: After ADR-123 self-hosted the fonts, `sw.ts` kept dead Google-Fonts CacheFirst routes (`fonts.googleapis.com` / `fonts.gstatic.com` + two evictable prefixes) for months — CSP tests asserted `index.html`/`globals.css` but never the SW, so the drift was invisible. When an ADR removes an external origin, assert the page/CSP AND the service worker (add a SW no-external-origin test alongside the CSP test).
- **web_search outage fallback**: When the `web_search` API returns empty for every query (service outage), fall back to `read_url` on authoritative doc pages — Vite serves LLM-friendly markdown at `/guide.md`, react.dev extracts cleanly, Cloudflare docs (JS-rendered) do not.

### UI/UX

- **Password toggle locator and geometry**: A password visibility button with `aria-label="Show password"` can be returned alongside the password input by Playwright's `getByLabel`; use `getByRole('textbox', { name: 'Password' })` for the field. Verify placement with bounding boxes because source utility classes do not prove generated CSS rendered the control on the intended edge.
- **Playwright viewport matrix scope**: A fixture-dependent `test.skip` callback must be registered at `describe` scope, not inside `beforeEach`; reuse `apps/tests/viewport-matrix.ts` and run the geometry test once in Chromium rather than multiplying it across browser/device projects.
- **Lazy reader-toolbar mount in WebKit**: Cross-browser reader tests can reach the redirected URL before the container-query toolbar has mounted. Shared toolbar helpers must wait for `[data-container-name="reader-toolbar"]` before resolving direct actions versus the overflow menu; retries can otherwise hide a real render race as a flaky test.

- **framer-motion removed (2026-07)**: Project migrated to CSS-only animations. `framer-motion` is no longer installed or imported in any source file. All test mocks for `framer-motion` (test-setup.ts, drawer.test.tsx, main.test.tsx, Modal.test.tsx, Input.test.tsx) have been removed as dead code. Historical note: When mocking `framer-motion` in Vitest, filtering out motion-specific props and mapping them to `data-*` attributes prevented React DOM warnings.
- **React RefObject readonly**: `React.RefObject<T>` has a readonly `current` property. Use `useRef<T | null>(initialValue)` instead when you need to mutate `.current` inside effects or event handlers.
- **react-hooks/exhaustive-deps with refs**: When capturing a ref's `.current` value inside `useEffect`, exclude the ref from the dependency array and capture the value at effect execution time.
- **Tailwind sr-only class**: `sr-only` is a built-in Tailwind utility (no config needed) — hides content visually but keeps it accessible to screen readers.
- **axe-core playwright**: `@axe-core/playwright` analyzes the page at the moment of invocation. Mocked API responses must be set up before navigation for meaningful results on pages that load asynchronously.
- **createPortal + test queries**: Components migrated to `createPortal` render content to `document.body`, not `render()`'s container. Change `container.querySelector()` to `document.body.querySelector()` in tests.
- **jsdom + focus trap offsetParent**: `useFocusTrap` filters focusable elements by `el.offsetParent !== null`. In jsdom, `offsetParent` always returns `null`. Fix: mock `Object.defineProperty(HTMLElement.prototype, 'offsetParent', ...)` in test setup.
- **Biome SolidJS rules fire on React**: Codacy's Biome engine flags `const fn = async () => { ... }` in React components with "Non-serializable expression must be wrapped with $(...)". This is a SolidJS-specific rule (`Biome_lint_correctness_useQwikValidLexicalScope`). Fix patterns:
  - **In components**: use `useCallback(async () => { ... }, [])` instead of bare `const fn = async () => {}`
  - **In test files**: use `vi.fn((key: string) => key)` instead of `const t = (key: string) => key;` — this avoids the Biome flag AND makes the function a spiable mock. Applies to any top-level arrow function assigned to a const in test files (translation helpers, mock callbacks, etc.).
- **`aria-label` on `<span>` not supported**: Codacy Biome flags `aria-label` on `<span>` elements. Use `role="status"` (or `role="img"`) to make the span accept `aria-label`, or switch to a `<button>` element.
- **`i18next/no-literal-string` fires on JSX attribute values**: The rule catches string literals in JSX attributes (e.g. `aria-label="Loading"`, `label="value"`), not only JSX text children. Extract the strings as module-level `const` values to bypass without any suppression comment.
- **React Compiler skips hooks with `eslint-disable react-hooks/exhaustive-deps`**: The React Compiler ESLint rule emits a warning and skips optimizing any hook that has a `react-hooks/exhaustive-deps` disable comment. Restructure the hook to not need the disable: use a `useRef` for the handler (keeps the listener stable without re-registering) and `mods.join(',')` as a dep string instead of spreading array values.
- **Admin reading-insights aggregation privacy (ADR-102b §7)**: Use `COUNT(DISTINCT user_email)` for reader count without exposing emails. Never `GROUP BY user_email` in admin aggregation. The pattern satisfies "aggregate summaries only" per ADR-102b without any reader-specific data leaking.
- **`type="button"` required on all buttons**: Codacy flags `<button>` without explicit `type` attribute. Always add `type="button"` to non-submit buttons.
- **`detect-object-injection` on test translation mocks**: Codacy ESLint flags `translations[key]` in `vi.mock()` translation helpers as `security/detect-object-injection`. The `key` parameter is always a string literal from the mock — no real injection risk. Preferred fix: use `Map<string, string>` with `.get(key)` and wrap `t` with `vi.fn()` — avoids both `detect-object-injection` (ESLint) and `useQwikValidLexicalScope` (Biome) with zero suppressions. Pattern: `t: vi.fn((key: string) => { const m = new Map([...]); return m.get(key) ?? key; })`.
- **Static hosts serve `/index.html` as the SPA entry, and React Router's `*` catch-all turns it into a client-side 404**: Render/GitHub Pages return the SPA shell (HTTP 200) for `/index.html`, but the router sees pathname `/index.html` — no route matches, so the catch-all renders `NotFoundPage`. Fix: add `<Route path="/index.html" element={<Navigate to="/" replace />} />` before the `*` route. When verifying locally, the PWA service worker serves the STALE precached bundle on revisit (the SW-update banner "A new version is available" is the tell) — close the agent-browser session (or use a fresh `--session`) after rebuilding, or the fix appears to not work.
- **A release workflow's `wrangler deploy --dry-run` is validation, not deployment**: release.yml removed the real deploy in PR #809; the worker's `*.workers.dev` DNS failed because nothing had ever deployed it. Also: `GET /api/health` must exist in the worker BEFORE any health check can distinguish a live API from a static host that swallowed `/api/*` — ADR-252's acceptance contract referenced an endpoint that didn't exist. When a deploy health check only asserts HTTP < 500, a 200 HTML SPA fallback passes; assert `200` + `{"ok":true}` (or JSON content-type) and fail closed (ADR-187).
- **A Cloudflare-native Worker API can ride the same Pages deployment via a Functions catch-all — no separate Worker deploy, no credentials, no CORS, no `VITE_API_BASE_URL`**: a `functions/api/[[path]].ts` that re-exports the Worker's Hono app (`app.fetch(context.request, context.env, context.ctx)`) is bundled automatically by the Pages build. Only `/api/*` matches (everything else falls through to static assets). **The `functions/` directory MUST live under the Pages project root (`apps/web/functions/`), NOT the repo root** — the Pages Git integration silently ignores a repo-root `functions/` (deployment has no `_routes.json`/`_worker.js`; `/api/*` returns a 404). `wrangler pages dev` and `wrangler pages functions build` DO find the repo-root location, so local verification can mislead you into thinking it deployed. Detect the miss by curling the deployed `/_routes.json` (404 = no functions). D1/R2/KV bindings are dashboard-configured on the Pages project; a Durable Object cannot be created inside a Pages project (rate limiting fails open — `rate-limit-client.ts` already degrades), and Email Sending is not a Pages binding (recovery falls back to logging). The web app's production `API_BASE_URL` (`window.location.origin`) already targets same-origin `/api/*`, so no frontend change is needed.
- **`working-directory` is invalid on a `uses:` step in GitHub Actions** — only `run:` steps support it; actions take it via a `workingDirectory:` input in `with:` (wrangler-action does). actionlint (`./scripts/validate-workflows.sh`) catches this at CI time.

### Aborted fetches: the API layer had the two classifications backwards (2026-09-20)

- **`abort(new DOMException('Request timeout'))` is not an `AbortError`**: a DOMException built without a name reports `name === 'Error'`, so `core.ts`'s `if (error.name === 'AbortError') log('api.timeout')` branch fired **only for caller cancellations** (React effect cleanup, superseded requests), while a real expired deadline fell through to `api.network-error`. The retry guard `error instanceof TypeError && error.message !== 'Request timeout'` could never match, so timeouts were logged as network failures and retried-on paper only. Fix: abort with `new DOMException('Request timeout', 'TimeoutError')`, branch on cancellation first (log `api.cancelled` at info), then on the named deadline; `isRetryable` now excludes both names explicitly. This inversion is why a normal reader mount looked like a hung reader in logs.
- **Cleanup-driven teardown is not an init failure**: `useReaderEpub` logged `reader.epub_init_failed` at error level when the effect cleanup destroyed the loader mid-await. It now logs `reader.epub_init_aborted` at info when the effect is no longer active, and reserves the error event (and `setError`) for genuine failures.
- **`apps/web` compiles against the ES2022 lib**: `Promise.withResolvers` (ES2024) is unavailable there even though `packages/reader-core` and `apps/tests` use it (they target ESNext). Test helpers in `apps/web` must use the executor form — with the one-line reason comment the repo rules ask for.
- **A hung CDP call plus zero browser processes means the browser was reaped, not that the app looped**: check `ps -eo pcpu,args | grep chrome` before theorising about client loops. In this harness that pattern matched idle-tab teardown between tool calls (machine idle, 8 GB free, no OOM record, no CPU-bound renderer), while CI's Playwright reader lanes passed throughout — so verify "no error was captured" only if the hooks provably ran in the failing document (in-page hooks die on a document reload; use document-start injection or keep the whole flow inside one cell).

### Audit entity-type drift, and why the managed browser "stalls" (2026-09-20, follow-up)

- **One enum, three copies, and the copy nobody checks wins**: `audit_log.entity_type` existed as `EntityTypeSchema` (7 values, driving the admin audit filter), the Worker's `EntityType` union (12), and the migration CHECK (12) — and none of them had `progress`, which `parseLocatorRow` writes for every reading-progress row. Type parametrized audit contexts as the entity union — then an unknown value cannot compile, and the CHECK constraint only ever sees values the union knows.

### GOAP-999 Wave 2 live verification — reader↔creator loop (2026-09-20)

### Grant management: stale rows after a save, and readers who could not be re-granted (2026-09-20, Wave 2 re-verification)

- **`use(promise)` + a module-level promise cache: clearing the cache does not re-render the consumer.** `GrantsPage` called `invalidateGrantsCache(bookId)` after a successful mutation, but the already-resolved promise the boundary had consumed kept rendering — the table showed the _pre-edit_ capabilities. ### Reference/style (COL-03): nullable resources, silent no-ops, and how the panel is driven (2026-09-21)

### COL-03 provenance: pinning, drift, and an async DTO that serialised as `{}` (2026-09-21)

- **`c.json({ ok: true, data: someAsyncHelper(...) })` writes `{}`**: replacing a synchronous DTO call with an `async` wrapper silently drops the payload — `JSON.stringify` sees a pending promise, and the tests fail far from the cause (`payload.data.status` undefined on a 201). Await the helper _inside_ the response object. The route tests caught it only because they assert on `data`.
- **A reader cannot pin what it cannot read**: `reference_revisions` was designed as a compose-time pin, but the reader never has access to `/creator/.../references`. The honest owner is the server at acceptance time (`POST /books/:id/feedback` records the book's current reference revisions); the distinction from a true compose-time pin only matters for offline replay, where the recorded set is still the one the server verified against.
- **"Never claim drift without evidence"**: items created before pinning existed store `NULL`, so `referencesDrifted` must default to false for an empty pin set — otherwise every historical item would suddenly look stale. Assert the unpinned case explicitly (`referencesDrifted({}, {...}) === false`).
- **Bare `vi.fn()` DB mocks return `undefined`, and iterating that explodes inside a caller**: adding one baseline query to a route broke three unrelated tests with `rows is not iterable`. `apps/worker/src/__tests__/fixtures.ts` now defaults the db mocks to the real client's contract (`queryAll → []`, `queryFirst → null`, `execute → { rows: [] }`), so a new query is a behavioural difference, not a crash.
- **Anchor provenance is testable without touching R2**: mutating `book_files.sha256` in the local Miniflare D1 flips live rows to `source_changed` and restoring it flips them back — the state is derived from that column and the stored evidence sha, not from the object store.
- **A page that reads a store only another page populates breaks on direct navigation**: `/creator/books/:bookId/feedback` took the book title from `useCreatorStore.books`, which only `/creator` fills, so opening the workspace URL directly (or reloading it) rendered the raw book id as its heading and as the export filename. Same class as the `use()`-cache staleness fix: the data was there, the component just never asked for it.
- **Reused i18n keys masquerading as field labels**: the reference form labelled its title input `ref.kindLabel` and its content textarea `ref.evidenceNote`, so a screen reader announced both with the wrong names. ### Dev environment & merge tooling: what actually blocks the gate (2026-09-22)

- **Local green ≠ CI green for Python pre-commit hooks**: the git-native `scripts/hooks/pre-commit` runs only `quality_gate.sh` (lint/typecheck/tests), while `.pre-commit-config.yaml`'s hooks (`end-of-file-fixer`, `trailing-whitespace`, `markdownlint`, `yamllint`, `gitleaks`, shellcheck@warning) run **only** in CI's `Pre-commit Hooks` job — and `pre-commit` itself cannot be installed locally on bullseye (no pip). ### GOAP-273 B1: quantized Transformers.js engine — runtime quirks & 0.5B prompt physics (2026-09-22)

Should be one of: cuda, webgpu, cpu.` So `device: 'auto'` must _mirror the runtime's vocabulary_ (WebGPU when an adapter is actually acquired, else `wasm` in browsers / `cpu` in Node), probing via an injectable `DeviceSelectionDeps` seam. WebGPU-advertised-but-failing retries the portable backend only under `auto`; a forced device fails closed.

### GOAP-273 B1 → live corpus attempts 1–3: the arena was the killer, `-t` is the fresh-process recipe (2026-09-23)

- **ORT's CPU memory arena — not model size — was the container-killer lever, and a "timeout" was the same cause read differently**: arena ON, one live review added `rssDeltaMb=+1398` (available 1593→1313, next item → vitest `Worker exited unexpectedly`); after #1189 (`session_options:{enableCpuMemArena:false}` in `defaultLoader`) the identical review added `+15..+99 MB` with a run floor of 1854–1860 MB. - **"One fresh process per item" is expressible as a vitest `-t` alternation, and filtering out the load test fail-closes every item**: `-t 'labelled on-demand load|item 5: conflicting'` runs ONLY load+item5 — `-t` is an unanchored regex over the FULL test name (suite chain included), non-matching tests flip to `skip`, and the `describe` body still executes at collection, so the shared capability exists while the load test's side effect (`pipe` set) survives for the item test in the same fork. - **`--max-old-space-size` does NOT govern native ORT memory — the probe recipe's 384 MB cap is JS-only**: the ~1.4 GB review spike is C++ arena/allocator RSS, invisible to V8 old-space, so the cap buys nothing for vitest runs of this suite while adding a V8-heap-OOM failure mode in the framework itself (misattributable to the container killer). Keep it where the documented creep is actually V8 heap (plain-node probe scripts, 1037→1902 MB), skip it for vitest + native-inference runs.
- **`incomplete_analysis` discards the evidence needed to fix it — diagnose with the gitignored probe first**: attempt 3 for item 6 ran with healthy memory (floor 1860 MB, `rssDeltaMb=99`) and still exhausted 3 sampled draws in 228 s (under the 300 s deadline) → pure contract failure, but `evaluate()` discards the raw text and the plugin logs nothing per draw. `packages/reader-core/b1-diag-probe.mjs` (gitignored, `E2E_DIAG_ITEM=6`) prints per-draw parse/grounding stages + `RAW:` output; run it before proposing ANY prompt/decoding/salvage change — all three are pinned sensors (`GENERATION_OPTIONS` pin, prompt tests, ADR-034 salvage contract).

### GOAP-273 B2 prep — official-docs verification of the B1 engine design (2026-09-23)

- **transformers.js v4 has NO grammar/JSON-constrained decoding**: the documented `generate()` `logits_processor` list (`docs/transformers.js/api/generation/logits_process`) contains no JSON/grammar processor and the README exposes only `bad_words_ids`/`force_words_ids`/`suppress_tokens` knobs — so contract reliability is officially unreachable by decoding and must stay prompt + retry + `validateEditorialFindings`; a DIY `LogitsProcessor` would be unsupported territory, not a fix.
- **`enableCpuMemArena:false` is officially valid but only at `pipeline()`/`from_pretrained()` time and only on Node/WASM bindings** (`onnxruntime.ai/docs/api/js/interfaces/InferenceSession.SessionOptions.html`) — confirms #1189's placement (`session_options` in `defaultLoader` and the probe); note `intraOpNumThreads` is Node-only and silently ignored by the browser WASM backend.
- **Pass a message array, not a pre-rendered string**: `pipeline('text-generation')` officially applies the model's chat template when given Chat messages (`docs/transformers.js/api/pipelines`); Qwen2.5-0.5B-Instruct's model card documents no JSON recipe, no `response_format`, and no recommended decoding settings (context 32,768; card has no Limitations section) — 0.5B structured-output reliability stays unverified upstream, which is exactly why ADR-999 requires per-item corpus evidence.
- **No official hard cancel exists**: `GenerationConfig.max_time` is a soft, per-call, current-pass-completing limit and ORT's `RunOptions.terminate` is WASM-only (`docs/transformers.js/api/generation/configuration_utils`) — the app's shared 300 s `Promise.race` deadline in `review()` is the only enforced mechanism; keep deadline policy there, never in generation config.
- **The diag probe silently depends on a second gitignored artifact**: `b1-diag-probe.mjs` imports `./.b1-fmt.bundle.mjs` (esbuild bundle re-exporting `buildChapters`/`buildMessages`/`parseCandidates`/… from the real format module) — a fresh container without it fails before any inference; rebuild it from `src/ai/plugins/transformers-editorial-format.ts` before diagnosing, and expect a one-time ~488 MB q8 model download (no HF cache survives container restarts).
- **Item 6's `incomplete_analysis` was stochastic sampling, not a contract break — and the probe's `ALL_STAGES_PASS` is necessary, not sufficient**: 2026-09-23 probe draws under identical prompt were draw 1 pass-but-invalid (question = the injected imperative with only first-letter capitalization ⇒ slips case-sensitive `isPromptEcho`'s `String.includes`; the live test then fails on `upload` in `explanation:question`), draw 2 pass-and-valid, draw 3 correctly nulled (demo id `x1` copied ⇒ grounding sensor). Never infer "model can't do item 6" from run-level `incomplete_analysis` alone — the verdict needs per-draw raw output, and a single live attempt samples one stochastic trajectory.
- **A one-character case change is enough to evade `isPromptEcho`**: the detector is exact-`includes` over prompt text (ADR-034, no regex), so the model re-casing the first letter of a copied sentence defeats it — fixed by normalizing case + whitespace on both sides with a hand-rolled ASCII-whitespace scan (no regex, linear, ADR-034-safe; fail-closed: only ever retries more draws, never invents a match). Levers (b)(c)(d) in plan 273 row 5 still await the product decision; don't ship prompt/decoding-adjacent changes without it.

### CI gates that never run, and how to check a coverage claim (2026-09-23)

- **`skipped` with `steps: []` is what a job whose `if` never became true looks like — and it is displayed nowhere near `failed`**: `e2e-smoke` and `bench` are `skipped` in **7/7 sampled runs (PR and push) while `dorny/paths-filter` logged `src`/`reader-core` = true**, with `build`'s legs already `success` 4 s earlier — so neither a stale workflow nor a race explains it. The `if` text was verified byte-identical to the copy GitHub executed (`contents/.github/workflows/ci.yml?ref=<head_sha>`); when source and behaviour disagree, diff them against the run's SHA instead of reading your working tree.
- **The cascade fixed in GOAP-267 moved one level downstream instead of disappearing**: `e2e-smoke` and `bench` are the only two jobs with `needs: [changes, build]` and **no `always()` guard**; the third job needing `build` (`performance-report`) has `always()` and is the only one of the three that runs. `build` itself only runs on PRs thanks to `if: always() && !contains(needs.*.result,'failure'|'cancelled')` because `lint`/`typecheck`/`test` are `if: github.event_name != 'pull_request'` — the downstream pair never got the mirror of that guard. Fix shape in GOAP-277 A1.
- **Nothing told us two accepted ADRs were unenforced**: ADR-201's "WebKit caught on every PR" and ADR-218's blocking `>20% ops/s` benchmark check both ride on jobs that never execute (only the scheduled `e2e-full` cron still runs a browser), while every required check stayed green. A check suite proves what ran, never what was silently skipped — see ADR-277's skip-visibility policy and issue #1193.
- **A coverage claim in this file needs a run id**: the §502 addendum asserted `e2e-smoke` covers PR smoke and contradicted §261 (which said not to assume it); the run data sided with §261. Per ADR-277 §3, cite the run where the job actually ran, or mark the claim as unverified.
- **GitHub gives no skip reason to machines**: skipped jobs have no logs and `annotations_count: 0`, and the job page only says "This job was skipped" behind a sign-in. Correlate which jobs share a `needs` edge instead of looking for a platform message.

### GOAP-277 execution: canary PRs for path-filtered gates, and four traps (2026-09-24)

- **A path-filtered gate cannot be verified by the PR that changes it — branch a throwaway canary off the fix instead**: editing only `.github/workflows/**` leaves `dorny/paths-filter` at `src=false`, so the gate skips _by design_ and proves nothing about the new `if`. `gh workflow run ci.yml --ref <branch>` is not an escape: this repo's integration token gets `HTTP 403 Resource not accessible by integration`, and `on.pull_request.branches: [main]` filters the **base**, so the canary must target `main` while branching _off_ the fix (the three-dot diff then holds both the guard and the `packages/**` touch). Add one clearly-labeled comment under `packages/**`, read the run, then close it unmerged; push the positive and negative canaries as two branches at once so their runs proceed in parallel — a second push to one PR instead cancels the first run, because `concurrency` uses `${{ github.workflow }}-${{ github.ref }}` with `cancel-in-progress: true` and `github.ref` is the same `refs/pull/N/merge` for every push.
- **A wrapped prose line starting with `#1201` fails `markdownlint` as MD018**: a bare issue reference at column 0 parses as an ATX heading missing its space (`no-missing-space-atx`), which red-lined CI's `Pre-commit Hooks` while every other hook — the quality gate included — had passed. Keep issue refs mid-line when wrapping prose, and grep new text for `^#[0-9]` before pushing.
- **CI's `Pre-commit Hooks` job runs the _minimal_ gate, and `verbose: true` output is easy to misread as a failure**: that job runs `pre-commit run --all-files`, whose `quality-gate` hook entry is `scripts/minimal_quality_gate.sh` (lint + typecheck + shellcheck, ~60 s), while the local git hook `scripts/hooks/pre-commit` calls the full `scripts/quality_gate.sh` (~4 min) and CI's full gate is the separate `Full Quality Gate` job. Success prints `Run quality gate .... Passed` inside a `- hook id: quality-gate` block that looks identical to the `- hook id:` + `Failed` pairing of a real failure — name the culprit by the word _after_ the hook id (markdownlint, in the 2026-09-24 run), never by the block's presence.
- **Codacy's `ACTION_REQUIRED` cleared by itself after a force-push**: immediately after `git push --force-with-lease` for a rebase the check sat at `ACTION_REQUIRED` and the PR read `BLOCKED`; the next push re-triggered analysis and it returned `success` with no manual re-run. Read `ACTION_REQUIRED` as "not analysed yet" first and re-check `gh pr view --json statusCheckRollup` on the following push before hunting for a Codacy finding.

### GOAP-276 Phase 0: five parallel work units and the shared files they fight over (2026-09-24)

- **`plans/ADR-INDEX.md` is the guaranteed merge collision for any set of parallel work units** — every unit appends a row, so N branches conflict pairwise. Two things made all five rebase cleanly: (a) appending each row _in numeric order_ tends to land concurrent rows in different tables/regions of the file (the ADR-only table near line 101 vs the GOAP+ADR table near line 171), so git auto-merges instead of conflicting; (b) resolve it yourself _before_ `atomic-commit` with `git add -A && git stash push -u -m <tag> && git reset --hard origin/main && git stash pop`, rather than trusting the orchestrator's `rebase --autostash`, which stops on the first conflict mid-push and leaves a half-rebased branch.
- **Assign plan/ADR numbers centrally at spawn time — never let parallel agents compute "the next free number"** — two implementation agents independently derived `279` from the same index and would have double-booked it; a late renumber means rewriting the ADR body, the index row and every cross-reference (the 279 → 280 renumber cost a full conflict re-resolution).
- **Editing a PR body fires `pull_request: [edited]` and re-runs every workflow on that PR** — so the normal `gh pr edit → gh pr merge` sequence shows `mergeStateStatus: UNSTABLE` with checks `pending` that had passed 30 s earlier _on an unchanged tree_. Confirm the re-run's own conclusion (`gh run view <id> --json status,conclusion`) before reading it as red, and prefer editing the body _before_ the final readiness check rather than racing the merge.
- **Codecov has no functions-coverage metric** — its statuses measure line coverage only, so the `48/60/70% functions` floors in AGENTS.md Tier 2 #4 can never be enforced by Codecov; vitest is their only possible enforcer, and any doc implying Codecov enforces them is wrong. Also, the real pass line is `target − threshold` (a `40% target, 2% threshold` gate passes at 38% — 15 pp under AGENTS.md's 55), and `base:` has been deprecated since July 2020; that pair is exactly how a frozen `codecov.yml` looked plausible while gating almost nothing (it was pinned to pre-Plan-223 values, with schema/testkit/ui absent entirely).
- **The local git hook and CI's Pre-commit job do not run the same hooks, so whitespace/format defects are CI-only failures**: `scripts/hooks/pre-commit` runs hook-config validation plus the full `scripts/quality_gate.sh`, but never the _pre-commit framework_ — `trailing-whitespace`, `markdownlint`, `yamllint` and gitleaks execute only inside CI's `pre-commit run --all-files`. Issue #1212 is the consequence: two trailing spaces at the end of one table row in `plans/ADR-INDEX.md` (introduced by #1209) sailed through every local commit and red-lined `main`'s push run `35984985785`. Until the local hook also runs the framework (that needs `pre-commit`, i.e. pip, which this container lacks), treat CI's `Pre-commit Hooks` job as the sole whitespace/format authority — run `pre-commit run --all-files` by hand before pushing wherever it is installed, and grep new text for `[ \t]$`.

### Hook parity, required checks, and release-gate execution (2026-09-26)

- **The local git hook and CI's Pre-commit job do not run the same hooks, so whitespace/format defects are CI-only failures** _(resolved by ADR-285)_: the local hook ran hook-config validation plus `quality_gate.sh`, which contains no whitespace, format, or markdown/yaml check, so the framework hooks executed only in CI. Issue #1212 is the consequence. The blocker recorded at the time — "needs `pre-commit`, i.e. pip, which this container lacks" — is **false as of 2026-09-26**: `pre-commit 4.6.0` and `pip` are on `PATH`. ADR-285 settles the policy as fail-closed on `--files` (not `--all-files`), with `SKIP_PRE_COMMIT_FRAMEWORK=true` as the only opt-out.
- **A fixer hook that rewrites the worktree must be followed by `git add -u`**: `trailing-whitespace` and `end-of-file-fixer` exit non-zero _and_ modify files, so without re-staging the commit records pre-fix bytes while every local gate is green — invisible unless you inspect `git show :file` rather than the file on disk.
- **A `files:` regex in `.pre-commit-config.yaml` can silently match nothing, and "Passed" does not mean "ran"**: shellcheck was configured with `\.(sh|bash)$`, but git names hooks by role, not extension — `scripts/hooks/pre-commit` has no suffix, so the filter matched none of them and every hook script shipped unlinted while the job reported green. Read the hook line (`Skipped` vs `Passed`), and probe with a **warning-level** defect (`cd /tmp` → SC2164): SC2006/SC2086 are style/info and are dropped by `--severity=warning`, so a backtick probe gives a false negative.
- **`gh api --jq` emits JSONL, not a JSON array, and that silently breaks every `map()` downstream**: piping it into `jq 'map(select(.name == $n))'` fails with `Cannot index string with string "name"` on every input, so a fail-closed gate reports all checks "missing" for the wrong reason. `--slurp` is **not** the fix — this `gh` rejects it alongside `--jq`. Use `gh api <ep> --paginate | jq -s '[.[] | (.check_runs // [])[] | …]'`, and `jq -e 'type == "array"'` before judging so a parser error is never reported as a missing check.
- **A joined verdict string hides partial failures — match each element**: `grep -qvE '(success|neutral)(,|$)'` over `completed/success,completed/cancelled` **passes**, because the string contains `success,`. Iterate with `IFS=',' read -ra` and test each element against `^(completed)/(success|neutral)$`. Superseded/cancelled predecessors are normal on any re-run commit.
- **Name-matching validators cannot tell a real gate from a string in a file**: `validate-gate-parity.sh` greps job names, so it reported ✓ for a `run:` block broken in two independent ways. Only **extracting the step and executing it against real API data** caught it — `actionlint` validates syntax, not semantics.
- **`GET /branches/{b}/protection` returning 404 does not mean the branch is unprotected**: that endpoint reports **classic** protection only. This repo already had an active ruleset (`15669639`: Codacy strict, CodeQL thresholds, thread resolution) that the 404 was blind to, and it was already described in this file — the note went unread because the 404 was over-trusted. Both mechanisms apply, so requirements union. Enumerate rulesets before adding protection.
- **A required status check that never runs is a permanent merge deadlock, and a skipped one is not**: `ci.yml` gates `lint`/`typecheck`/`test` behind `if: github.event_name != 'pull_request'`, so on a PR they report `skipped` under a name still showing an uninterpolated matrix expression. Requiring them would block every PR forever. Rule: require a context only after observing it produce a check run on a real PR head via `GET /commits/<sha>/check-runs`.
- **yamllint's `comments` rule and prettier's YAML printer are irreconcilable**: yamllint wants **two** spaces before `#`; prettier always emits one, so on a formatted repo it warns on all 74 `uses: …@<sha> # vX.Y.Z` comments and the gate's zero-warning policy fails a clean tree. Restoring the spacing does not work — prettier rewrites it — so the rule is off for workflows and prettier owns YAML. The warning looks like shellcheck's `-f gcc` output but is yamllint's.
- **A test that reads a source file and asserts on its quoting is a formatting canary**: `design-tokens.test.ts` asserted `toContain('[data-theme="sepia"]')`, so prettier normalising CSS attribute quotes turned a formatting change into a red test. Assert content, not the formatter's choice of quoting.
