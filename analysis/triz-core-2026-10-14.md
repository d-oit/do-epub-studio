# TRIZ core analysis — open GitHub issues #1323–#1330

**Date:** 2026-10-14
**Status:** Analysis before implementation
**Scope:** All eight open issues #1323–#1330 and open PRs #1322/#1331.
**Evidence boundary:** Repository source, current issue bodies, PR/check records, and the scheduled CI run are the evidence. Reported hotspot scores are estimates until measured.

## Current system contradictions

1. **Offline mutation availability vs duplicate effects and silent data loss.** The client must retry after network failures and across tabs, while the server must not apply a mutation twice. The existing queue encrypts entries and the server already has mutation-ID deduplication for comment creation, but retries are process-local, failure handling can discard/block work, and edits lack a base version. Treat transport as at-least-once; give each logical mutation a stable ID, make server effects idempotent, coordinate drains with Web Locks plus a local fallback, and retain terminal/conflicting payloads for explicit recovery. Do not claim network-level exactly-once delivery.

2. **Conflict detection vs API compatibility.** An offline edit must not overwrite a newer collaborative edit, while existing reader clients and endpoints keep their current contract. Add explicit base-version/revision metadata and return a distinguishable conflict response; preserve the user's local payload and provide a resolution path. Keep authorization and tenant checks before conflict disclosure.

3. **Re-anchor accuracy vs bounded latency.** Annotation identity must survive DOM/content changes without blocking reading or selecting a plausible but wrong passage. Use ordered exact-CFI, position, then quote/context strategies; make each independently testable; cap input/work; report confidence and preserve the old locator whenever the match is not strong. Move work to a Worker only when measurements show a main-thread problem. A low-confidence match becomes an orphan/review item, not an automatic rewrite.

4. **EPUB security vs legitimate EPUB3 content.** Removing every SVG/CSS construct would break illustrations and typography; permissive handling enables script execution or external requests. Keep explicit allowlists, reject active markup/event attributes and external CSS/SVG references, and pin both hostile and valid-content vectors. Fuzz deterministic parser inputs and assert security invariants plus preservation of supported content.

5. **Revision history vs large migration completion.** New EPUB bytes must become an immutable, retry-safe revision while existing anchors remain recoverable; migration may be interrupted or ambiguous. Use content hashes and a stable revision identity, persist migration progress and per-annotation outcomes in bounded batches, retain original anchor snapshots, and make retries idempotent. Preserve orphaned comments rather than deleting or silently relocating them.

6. **Offline full-text search vs UI-thread latency and local-data exposure.** Search needs to work after the network disappears, but parsing/indexing/querying must not stall reading or persist plain text outside the app's existing privacy boundary. Build and query a revision-keyed token index in a dedicated Worker, persist it in the existing IndexedDB encryption model, return snippets/CFIs rather than chapter bodies, and invalidate it with the corresponding book/revision lifecycle.

7. **Hook modularity vs EPUB lifecycle stability.** Focused hooks should separate loader, rendition, navigation, and annotation ownership without creating duplicate rendition instances, reloads, or CFI loss. Keep one composition facade and one owner per resource; isolate high-frequency state only after measuring actual render behavior. Do not add a global store by default.

8. **Deterministic E2E vs backend realism.** The scheduled lane must cover real user-visible behavior, while test fixtures need deterministic API results and must not depend on an absent localhost Worker. Mock only deliberately owned API contracts or start a local Worker with local-only D1; never hide connection failures, lengthen timeouts, or weaken assertions as a substitute for fixing setup. Wait for rendered/observable states, not arbitrary sleeps or `networkidle` when background APIs remain active.

## Resolution constraints

- Run the scheduled failure's exact affected flows before and after changing fixtures or server setup; preserve accessibility scans and real auth behavior.
- Reuse existing mutation IDs, encrypted IndexedDB helpers, tenant guards, auth capabilities, annotation locator fields, and schema/migration conventions.
- Preserve existing public API behavior except for explicit, tested revision/conflict/export additions.
- Profile the 100-annotation/50-KB benchmark and render behavior on recorded hardware; claim a 40% complexity change only if the repository's actual baseline tool confirms it.
- Do not weaken CI required contexts, sanitizer policy, test assertions, or authorization to make checks green.

## TRIZ solution and ideal final results

### Resolved: Contradiction 1 — retries vs duplicate/lost mutations

**IFR:** A logical edit reaches the server after any reconnect or reload, without a second durable effect and without deleting the user's payload.
**Separation:** Time and system level — retries reuse the same mutation identity; durable deduplication lives at the server write boundary, while browser coordination reduces concurrent dispatch.
**Solution:** Stable per-item mutation IDs, a Web Lock when supported, an in-process fallback, bounded jittered retry for network/429/5xx, and retained terminal failures. Server idempotency remains the final guard if two tabs race.
**Why better:** It separates delivery attempts from the mutation's identity and effect; transport remains at-least-once without pretending to provide exactly-once delivery.
**New contradictions:** None known. Unsupported Web Locks can still permit duplicate requests, but stable IDs and server deduplication prevent duplicate effects.

### Resolved: Contradiction 2 — optimistic conflict checks vs compatible API behavior

**IFR:** New offline edits never overwrite a newer version, while existing callers retain their established API behavior.
**Separation:** Condition — enforce base-version comparison when a caller supplies the new version token; legacy callers keep their prior route contract until migrated.
**Solution:** Persist an integer server revision, have updated clients send the base revision, and return a typed conflict response only after authentication, tenant, ownership, and capability checks. Keep both local and canonical versions available to the existing conflict UI.
**Why better:** Conflict detection is localized to edits that can supply a version, and authorization remains the first observable boundary.
**New contradictions:** None known. The optional request field is temporary compatibility, not a second public API path; all current client callers must migrate.

### Resolved: Contradiction 3 — accurate re-anchoring vs bounded latency

**IFR:** An annotation returns to the same passage when possible, without blocking the reader or silently selecting a different passage.
**Separation:** Condition and system level — cheap exact/position checks run first; bounded quote/context scoring is reserved for misses and can move to a Worker only if profiling justifies it.
**Solution:** Independent exact-CFI, text-position, then exact quote/prefix/suffix and fuzzy-context strategies return a locator, strategy, and confidence. Cap text, chapters, candidates, and elapsed work. Below the documented threshold, keep the old locator and mark needs-review.
**Why better:** The system spends work only when cheaper strategies fail, and uncertain results preserve source evidence.
**New contradictions:** None known. A stale CFI is expected after a revision and is why later strategies remain available.

### Resolved: Contradiction 4 — safe EPUB sanitization vs valid EPUB3 features

**IFR:** Untrusted EPUB content cannot execute script or cause external resource requests, while supported illustrations and typography remain intact.
**Separation:** Local quality — allow only the required tags, attributes, CSS properties, and same-document fragment references for each content context; reject active/external forms at the parser boundary.
**Solution:** Keep XHTML, SVG, CSS, and MathML handling explicit; block scripts/events, `foreignObject`, external SVG `use`, external `url()` and `@import`; preserve tested safe inline SVG/use references, MathML, and EPUB typography. Deterministic fuzz cases assert both no active/external sinks and retained benign nodes.
**Why better:** Security is expressed as a narrow per-context allowlist instead of either a permissive pass-through or a blanket removal of useful content.
**New contradictions:** None known. Any unsupported legitimate feature is surfaced by a valid-content regression vector before policy changes ship.

### Resolved: Contradiction 5 — immutable revisions vs interrupted migration

**IFR:** A repeated upload and interrupted migration converge on one revision and one durable outcome per annotation, without erasing old anchors.
**Separation:** Time and segmentation — identify bytes once, then process annotations in bounded resumable batches against immutable source/target revisions.
**Solution:** Hash the uploaded content, reuse the persisted revision identity on repeated completion, create a unique migration for each source/target pair, and persist progress plus each annotation's source snapshot, new locator, confidence, and outcome. Replays are idempotent; ambiguous/deleted passages stay orphaned.
**Why better:** Upload identity and migration progress survive process restarts and do not depend on an in-memory job.
**New contradictions:** None known. Hashing and storing prior locators add bounded storage, accepted to preserve auditability and user content.

### Resolved: Contradiction 6 — offline search vs UI latency and data privacy

**IFR:** Search after caching returns a useful result within the measured target, without a network or main-thread chapter scan, and without plaintext index persistence.
**Separation:** Space and system level — the Worker owns tokenization/query work; IndexedDB remains the durable local store under the app's existing encryption boundary.
**Solution:** Build and query a compact per-revision index in a dedicated Worker, persist the serialized index encrypted in IndexedDB, transfer only index/query inputs and return snippets, counts, and CFIs. Remove stale indexes with their book/revision lifecycle.
**Why better:** CPU-heavy work is isolated from rendering, while offline persistence inherits the established sensitive-data policy.
**New contradictions:** None known. Worker transfer/encryption overhead is measured in the representative benchmark and can shape the compact index format.

### Resolved: Contradiction 7 — focused reader hooks vs one stable EPUB lifecycle

**IFR:** Loader, rendition, navigation, and annotation responsibilities can be tested separately while one archive/rendition retains its CFI through theme and font changes.
**Separation:** Segmentation — give each hook one lifecycle responsibility and keep the existing facade as the composition boundary.
**Solution:** Extract the four named hooks around stable refs and explicit dependencies; move theme/font/spread updates onto the existing rendition; isolate high-frequency location state only if render measurements support it.
**Why better:** Independent test seams do not create duplicate resource owners or an unmeasured global state layer.
**New contradictions:** None known. Hook dependency changes are checked by a CFI-preservation browser scenario.

### Resolved: Contradiction 8 — realistic E2E behavior vs deterministic isolation

**IFR:** Every E2E scenario exercises its intended consumer behavior without accidental dependency on an absent backend or hidden network failures.
**Separation:** Condition — mock only endpoints owned by a UI contract test; use a local Worker and local-only D1 where server behavior is part of the scenario.
**Solution:** Complete fixture coverage for expected background API calls, fail visibly on unexpected requests, and start local services only for real route/integration cases. Trigger smoke tests for `apps/tests/**`; await rendered state and use controlled retries rather than wall-clock sleeps.
**Why better:** Tests retain deterministic inputs and real behavior at the boundary they claim to cover, with no timeout/suppression escape hatch.
**New contradictions:** None known. The local service path costs setup time but is isolated from production data.

## Derived component boundaries

| Component                              | Contract                                                                                                                                                                 |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Offline outbox ↔ comment/progress APIs | Stable mutation ID per queued logical mutation; base server revision on edits; typed permanent failure or conflict; durable client failure metadata                      |
| Annotation/revision storage            | Content hash and stable `book_files` identity; immutable source locator snapshot; unique source/target migration; per-annotation confidence/outcome and resumable cursor |
| Reader-core re-anchor                  | Pure ordered selectors return the candidate locator, strategy, and confidence; bounded inputs/work; no UI or database dependency                                         |
| EPUB sanitizer                         | Context-specific allowlists; no script/event/external-resource sinks; regression corpus protects supported SVG, MathML, and typography                                   |
| Search Worker ↔ IndexedDB              | Revision-keyed build/query/clear messages; encrypted persisted index; result contract contains chapter/title/snippet/count/CFI, never full chapter text                  |
| Reader hook facade                     | `useEpubLoader`, `useEpubRendition`, `useEpubNavigation`, and `useEpubAnnotationBridge` each own one concern; `useReaderEpub` composes them                              |
| Export route                           | Validated reviewer/tag/status filters; authorization before query; Markdown, W3C-profile JSON-LD, CSV, and JSON serialize user content safely                            |
| Playwright setup                       | Fixture-owned expected API reads; local-only Worker/D1 for true route scenarios; changed E2E paths trigger smoke execution                                               |

No additional system-level contradiction remains under these boundaries. Secondary costs (encrypted index CPU/storage, migration history storage, and local Worker startup) are measured and constrained rather than hidden.
