# TRIZ Core Analysis — Structured EPUB Authoring Workspace and EPUB 3 Export Pipeline

**Date:** 2026-11-05
**Scope:** GitHub issue #1431 (Build a structured EPUB authoring workspace and EPUB 3 export pipeline).
**Status:** All five contradictions identified and classified; resolutions documented in `plans/003-system-design.md` and companion `plans/1020-adr-epub-authoring-and-packager.md`.

## System and parameters

The system is a Cloudflare Worker (D1 SQLite database, R2 object storage) and React SPA (`apps/web`), shared schemas (`@do-epub-studio/schema`), and core reader engine (`packages/reader-core`). Relevant parameters: manuscript authoring flexibility, XHTML/EPUB 3 syntactic conformance, security (XSS / default-deny), Worker memory and latency bounds, publication revision immutability, preview fidelity, and granular authorization.

---

### Contradiction 1 — Authoring expressiveness versus EPUB 3 conformance and script security

**Improving:** Authoring flexibility and speed (structured chapter editing: headings, formatting, lists, tables, links, images).
**Worsens:** Security (injection of active content, scripts, unescaped XML entities) and EPUB 3 validation failure (ill-formed XHTML, unmanifested assets).
**Why:** Allowing arbitrary HTML input can leak script execution or malformed XML that fails EPUBCheck or crashes the sandboxed reader. Constraining authors to raw XML makes the workspace unusable.
**Reality:** Confirmed by `packages/reader-core/src/sanitizer.ts` (strict default-deny policy) and W3C EPUB 3.3 §4.2 (Content Documents must be valid XML).
**Type:** Technical.

**TRIZ Principles Available:**

- Segmentation (separate semantic structured model from serialized XHTML)
- Extraction (strip all active content and event handlers)
- Local Quality (restrict tags to safe EPUB Content Document vocabulary)

---

### Contradiction 2 — Continuous draft autosave versus revision immutability and concurrency

**Improving:** Authoring safety (continuous draft autosave, conflict detection, chapter reordering).
**Worsens:** Storage churn, database transaction lock contention, and the integrity of published immutable book revisions.
**Why:** Readers and validation reports depend on immutable book revisions (`book_files.sha256`, R2 object permanence). An active authoring manuscript undergoes frequent rapid mutations that cannot overwrite existing revision bytes.
**Reality:** Confirmed by `apps/worker/src/routes/admin/books.ts` and `plans/1017-adr-epub-conformance-and-evidence.md`: revisions are strictly append-only.
**Type:** Physical (manuscript must be mutable during drafting, but immutable once published).

**TRIZ Principles Available:**

- Time separation (mutable draft state in D1 during authoring; immutable revision committed to R2 on explicit publish)
- Condition separation (draft vs published revision states)
- Asymmetry (drafts use optimistic version locking `draft_version`; published revisions use SHA-256 digests)

---

### Contradiction 3 — Bounded Worker compute/memory limits versus deterministic EPUB 3 ZIP packaging

**Improving:** Native, deterministic generation of valid EPUB 3 packages directly within the platform.
**Worsens:** Cloudflare Worker execution constraints (128 MB RAM, short CPU execution slices).
**Why:** Constructing an EPUB archive requires a root directory structure, uncompressed `mimetype`, `META-INF/container.xml`, `content.opf` with complete metadata/manifest/spine, `nav.xhtml` navigation document, XHTML chapter documents, and bundled images/stylesheets. Buffering large publications into memory risks Worker OOM.
**Reality:** Confirmed by `packages/reader-core/src/__tests__/fixtures/zip-builder.mjs` and Cloudflare Worker memory caps.
**Type:** Technical.

**TRIZ Principles Available:**

- Segmentation (modular package component generation)
- Partial Action (stream entries sequentially with known CRC-32 and lengths)
- Dynamicity (support client-side browser packaging with web streams alongside Worker packaging)

---

### Contradiction 4 — Production reader preview fidelity versus authoring keystroke latency

**Improving:** Authoring preview fidelity (seeing exactly how the chapter renders in the production `@intity/epub-js` reading view).
**Worsens:** Authoring responsiveness and latency if a full EPUB ZIP is rebuilt, hashed, and mounted on every text keystroke.
**Why:** Re-implementing a separate preview renderer creates behavioral drift; re-bundling the entire publication ZIP on each edit introduces substantial lag.
**Reality:** Confirmed by `apps/web/src/features/reader/ReaderPage.tsx`: loading a full EPUB involves manifest parsing, CFI calculation, and iframe initialization.
**Type:** Technical.

**TRIZ Principles Available:**

- Time separation (immediate chapter preview via sanitized live DOM; full publication EPUB preview upon chapter switch or tab request)
- System-level separation (delegate live chapter layout to sanitized content viewport; delegate whole-book preview to standard reader)

---

### Contradiction 5 — Explicit authoring authorization versus broad administrative privilege

**Improving:** Enabling manuscript creation and editing by assigned book authors.
**Worsens:** System security if authoring capabilities are conflated with global admin access or granted automatically to readers/commentators.
**Why:** Readers only hold grant tokens for reading; feedback creators only comment on revisions. Conflating authors with admins risks privilege escalation across tenant books.
**Reality:** Confirmed by `apps/worker/src/auth/` and `packages/schema/src/schemas/auth.ts`: permissions are role-scoped.
**Type:** Technical.

**TRIZ Principles Available:**

- Local Quality (define explicit `author` role and book-level `authoring` permission distinct from `admin` and `reader`)
- Segmentation (fenced API routes for `/api/author/*`)
