# TRIZ Core — EPUB authoring acceptance gaps (2026-11-08)

## System

Complete the EPUB 3 authoring workflow defined by issue #1431 and accepted ADR-1020. The system includes the D1 draft/API, author permissions, local media, the browser editor, shared EPUB packager, reader-core preview, and immutable publication storage.

## Relevant system properties

- EPUB byte determinism and publication identity.
- Conflict-free autosave across concurrent browser sessions.
- Book-scoped author access, distinct from reading and creator-feedback access.
- Fidelity between the author preview and the production reader.
- Immediate editing feedback and bounded browser/Worker resource use.
- Local image/CSS authoring and safe publication.
- Immutable revision integrity while drafts and asset libraries remain mutable.
- Accessible, localized authoring controls and recoverable failures.

## Contradictions

### Contradiction 1 — deterministic bytes and meaningful package metadata

**Improving:** Repeatable EPUB bytes and content-addressed revision identity.

**Worsens:** Accurate `dcterms:modified` and publication identifier values if those values are generated implicitly during packaging.

**Why:** The current packager uses `Date.now()` as fallback input for package identity/modified metadata. Repacking unchanged draft content can therefore change archive bytes and SHA-256.

**Reality:** Real. The fallback is in `packages/reader-core/src/packager/packager.ts`; current publishing calls `packageEpub3(publication)` without a persisted timestamp or explicit identifier. ADR-1020 requires deterministic packaging and content-addressed immutable output.

**Type:** Technical.

**TRIZ Principles Available:**

- 1. Segmentation — separate stable manuscript identity from package-build time.
- 10. Prior action — persist the draft snapshot timestamp before packaging.
- 23. Feedback — verify deterministic bytes and archive identity in an integration test.
- 35. Parameter change — derive the modified timestamp from the saved draft version, never the build clock.

**Resolution status:** Unresolved in implementation.

### Contradiction 2 — autosave convenience and concurrent-draft safety

**Improving:** Automatic saving without interrupting author workflow.

**Worsens:** Protection against silently overwriting another session's saved changes.

**Why:** `SaveManuscriptDraftSchema.expectedVersion` is optional, and `PUT /books/:id/manuscript` reads the current version before a separate upsert. A caller may omit the version; simultaneous saves can both pass the read/check and write the same next version.

**Reality:** Real. Both conditions are present in `packages/schema/src/schemas/manuscript.ts` and `apps/worker/src/routes/author.ts`. The existing conflict response is useful but does not make the check-and-write atomic.

**Type:** Technical.

**TRIZ Principles Available:**

- 1. Segmentation — compare-and-swap the version in the write itself.
- 23. Feedback — return the winning draft/version on conflict.
- 24. Intermediary — use D1's conditional `UPDATE ... WHERE draft_version = ? RETURNING` as the concurrency boundary.
- 10. Prior action — require the client to send the version it loaded.

**Resolution status:** Unresolved in implementation.

### Contradiction 3 — author capability security and access usability

**Improving:** Strict book-scoped protection for editing, uploading, and publishing.

**Worsens:** Usability for non-admin authors if the system accepts only global admin credentials.

**Why:** Current `authorAuth` delegates to `requireAdminAuth`; reader grants and creator-feedback permissions do not express authoring rights. Simply reusing either would let readers or feedback creators mutate manuscripts.

**Reality:** Real. `apps/worker/src/middleware/auth.ts` contains admin-only author authorization; `book_access_grants` has reading/comment/offline capabilities but no authoring capability; invitation roles are only `reader` and `creator`. ADR-1020 explicitly requires a separate author role/capability.

**Type:** Technical.

**TRIZ Principles Available:**

- 1. Segmentation — keep `authoring_allowed` separate from reading, comments, and offline flags.
- 3. Local quality — authorize each request against the exact book ID and current active grant.
- 24. Intermediary — use an explicit book-scoped author invitation/grant rather than inferring from other roles.
- 23. Feedback — revoke access by invalidating existing sessions when the author capability changes.

**Resolution status:** Unresolved in implementation.

### Contradiction 4 — reader-engine fidelity and keystroke latency

**Improving:** Preview fidelity to the production reader's EPUB parsing, sanitization, CSS, navigation, and layout.

**Worsens:** Editor responsiveness if the full EPUB is repackaged and reloaded after every edit.

**Why:** Current preview renders the safe author-content AST directly in React. It avoids an HTML injection sink, but does not exercise the production EPUB reader. Rebuilding the package on each keystroke would add synchronous ZIP work and reader reloads to the editor path.

**Reality:** Real. `AuthorWorkspacePage.tsx` renders `renderAuthorContent`; `createEpubLoader` accepts in-memory `Uint8Array` packages and is the production reader-core loader. ADR-1020 requires production-reader preview and no keystroke lag.

**Type:** Technical.

**TRIZ Principles Available:**

- 1. Segmentation — preserve an immediate safe editor preview; make full-reader preview an explicit action.
- 10. Prior action — snapshot/save the current draft before starting a reader preview.
- 15. Dynamicity — create and destroy the reader rendition only while the full-preview surface is active.
- 28. Mechanics substitution — use the production `createEpubLoader` on an in-memory package rather than a second renderer.

**Resolution status:** Partially resolved: the current AST preview is safe and immediate, but reader-engine fidelity is absent.

### Contradiction 5 — local media capability and untrusted-file/resource risk

**Improving:** Authors can manage and reuse local images and stylesheets, including a cover.

**Worsens:** Parser attack surface, network egress risk, upload memory, and invalid EPUB risk.

**Why:** Untrusted bytes and CSS can contain malformed formats, active SVG/script, remote URLs, oversized payloads, or unsafe paths. The generic Worker body limit is 1 MiB, while the authoring requirements need bounded media uploads larger than that limit.

**Reality:** Real. `apps/worker/src/middleware/body-size-limit.ts` caps requests at 1 MiB and exempts only admin EPUB streaming. The current publication schema/packager have no persisted local asset model; archive safety checks exist but do not validate or package editor assets.

**Type:** Technical.

**TRIZ Principles Available:**

- 1. Segmentation — separate bounded asset upload and storage from draft JSON and package generation.
- 3. Local quality — allow only explicit MIME/signature pairs, safe CSS, generated package paths, and per-file/total byte limits.
- 2. Extraction — remove active/remote CSS constructs and disallow SVG/script-bearing formats rather than trying to repair them.
- 24. Intermediary — reference media by validated asset IDs, not author-supplied archive paths.

**Resolution status:** Unresolved in implementation.

### Contradiction 6 — mutable drafts/assets and immutable publication revisions

**Improving:** Authors can continue editing manuscript metadata and media after publication.

**Worsens:** Published revision immutability and reproducibility if a package points at mutable draft assets or is overwritten in place.

**Why:** The current publish route stores each package under a random object key and does not load draft assets. Adding media without snapshotting it into the EPUB would make output depend on mutable external state; using random keys alone does not provide content-addressed identity.

**Reality:** Real. `apps/worker/src/routes/author-publish.ts` packages the draft without assets and writes to `books/{bookId}/{randomFileId}.epub`; ADR-1020 requires immutable, content-addressed revisions and a package snapshot.

**Type:** Technical.

**TRIZ Principles Available:**

- 1. Segmentation — keep mutable draft records separate from immutable packaged bytes.
- 10. Prior action — resolve and validate every referenced asset before packaging.
- 2. Extraction — include only referenced, validated assets in the publication snapshot.
- 35. Parameter change — address the stored EPUB by its SHA-256 and never overwrite a different byte sequence.

**Resolution status:** Partially resolved: stored EPUB rows are immutable, but storage identity is random and assets are not snapshotted.

## Verification checklist

- Every contradiction above is grounded in the current source or accepted ADR, not inferred from an absent feature.
- The accepted ADR has already chosen the target behavior; this analysis identifies implementation gaps and does not reopen those product decisions.
- Unresolved contradictions must be resolved with `triz-solver` before implementation.
