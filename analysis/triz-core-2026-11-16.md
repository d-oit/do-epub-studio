# TRIZ Core Analysis: Author Preview Parser Availability

## System

The author preview packages the current manuscript with `packageEpub3()` and loads those bytes through `createEpubLoader()`. The loader prefers `epub-parser.worker.ts` for archive validation and already has a main-thread validation fallback when a Worker emits a load error. The uncovered state is a Worker that never sends its `ready` handshake and never emits `error`.

## System properties

- **Preview availability:** the preview should finish instead of remaining in a loading state until the 30-second EPUB load timeout.
- **Main-thread responsiveness:** archive validation should not unnecessarily block the reader UI.
- **Validation safety:** both worker and fallback paths use the same bounded `validateArchive()` rules.
- **Normal-path cost:** a healthy worker should remain the preferred parser.

### Contradiction 1 — Technical

**Improving:** Preview availability when the module Worker does not initialize.
**Worsens:** Main-thread responsiveness if validation falls back while a slow Worker is still starting.
**Why:** The existing fallback runs archive validation on the main thread. Starting it immediately avoids a stuck preview but can consume main-thread time on large archives.
**Reality:** This is real, not assumed. In the local author workspace, the preview remained in `Packaging and opening the EPUB preview…`, `createEpubLoader` timed out after 30 seconds, and an independent module Worker emitted neither `ready` nor `error` during a 10-second observation. The existing worker fallback is only entered from `onerror`, so this state has no completion path before the outer timeout.

**TRIZ Principles Available:**

- **1 — Segmentation:** keep the worker as the normal path and apply fallback only to pending parses when startup fails.
- **10 — Preliminary action:** bound worker initialization before any unbounded parse wait.
- **15 — Dynamicity:** allow the parser strategy to change from worker to fallback based on observed readiness.
- **25 — Self-service / separation in time:** try the worker first, then use the existing fallback after a bounded readiness interval.

**Status:** resolved in `analysis/triz-resolution-2026-11-16.md` (Contradiction 1).

## Contradiction 2 — responsive author preview

**System:** The author preview packages a saved publication once, then displays the generated EPUB in an existing epub.js rendition inside a responsive container.

**Parameters:** Viewport fidelity, current reading position, and preview loading/repackaging cost.

### Contradiction 2 — Technical

**Improving:** The preview must remain visible and correctly sized after a viewport change, including device rotation or responsive breakpoint changes.
**Worsens:** Rebuilding the EPUB and rendition on every resize would repeat packaging and parsing and could lose the current reading position; leaving the rendition untouched can leave its iframe at zero size.
**Why:** The author workspace container resizes, but the EPUB rendition was sized only at creation. Recreating the rendition would recover dimensions at a cost to continuity and responsiveness.
**Reality:** Reproduced in the browser at 1280×900 → 768×1024 → 390×844 while Preview remained mounted. The author preview container retained positive dimensions and the document had no horizontal overflow, but the rendition iframe became 0×0 at each dynamic resize. Reloading at 390×844 and opening Preview rendered the chapter in a 356×572 iframe. The installed epub.js type declares `Rendition.resize(width, height)`.

**TRIZ Principles Available:**

- **1 — Segmentation:** observe only the preview container and resize its existing rendition when that container changes.
- **15 — Dynamicity:** adapt the live rendition to the container instead of rebuilding the EPUB.

**Status:** resolved in `analysis/triz-resolution-2026-11-16.md` (Contradiction 2).
