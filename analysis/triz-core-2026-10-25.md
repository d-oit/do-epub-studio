# Demo deployment contradictions

## Contradiction 1 — public demo access and production isolation

**Type:** technical.
**Improving:** a reviewer can use the deployed reader and administrator demos.
**Worsens:** enabling published demo credentials against production exposes real data.
**Why:** the deployment runbook claims production flags enable a demo, but the runtime and seed deliberately reject production.
**Reality:** source-confirmed; production rejection is intentional, while the preview D1 binding is already distinct.
**TRIZ Principles Available:** segmentation, local quality, condition separation.

**IFR:** a reviewer uses complete demo data without gaining production access.
**Separation:** space and condition.
**Solution:** provision only the explicit preview D1/R2 bindings, verify they differ from production, and require an explicit preview-admin opt-in. Keep production rejection unchanged.
**New Contradictions:** none; provision only disposable preview resources and never deploy or seed automatically on a production release.

## Contradiction 2 — successful login and incomplete book provisioning

**Type:** technical.
**Improving:** account-only seeding works with a minimal SQL transport.
**Worsens:** deployed reader login succeeds but cannot retrieve an EPUB.
**Why:** the account seed creates a placeholder without R2 data or a book_files record.
**Reality:** source-confirmed; the placeholder is explicitly documented, so a separate provisioning step is required.
**TRIZ Principles Available:** segmentation, nesting.

**IFR:** the preview setup produces a readable book and matching account grants.
**Separation:** system level.
**Solution:** retain the reusable account seed and add a preview provisioning command owning migrations, sample EPUB upload and file metadata. Validate actual chapter content in the live browser journey.
**New Contradictions:** none; generated assets remain untracked and existing non-demo content is never replaced.
